## Question 1(a): Monitor vs. Scoreboard
**Differentiate between a monitor and a scoreboard in terms of purpose, data handling, and position in a verification environment. (5 M)**

| Feature | Monitor | Scoreboard |
|---------|---------|------------|
| **Purpose** | To passively observe pin-level activity on the DUT interface and convert it into high-level transaction objects. | To receive actual transactions from monitors and compare them against expected transactions generated by a reference model to verify functional correctness. |
| **Data Handling** | Captures raw signals (1s and 0s) over time and reconstructs them into structured packet/transaction objects without modifying the DUT state. | Buffers actual transactions and expected transactions, compares them data-field by data-field, and flags matches or mismatches. |
| **Position** | Located inside the Agent, connected directly to the Virtual Interface alongside the Driver. | Located at the Environment level, receiving data via TLM Analysis Ports from the Monitor and the Reference Model. |

## Question 1(b): `logic` vs `wire`/`reg`
**Why is the logic data type preferred over wire and reg in modern SystemVerilog designs? Explain with reference to procedural and continuous assignments. (5 M)**

In traditional Verilog, the choice between `wire` and `reg` was strictly dictated by the context of assignment, which often caused confusion:
- `wire` had to be used for **continuous assignments** (using `assign`).
- `reg` had to be used for **procedural assignments** (inside `always` or `initial` blocks).

SystemVerilog introduced the **`logic`** data type to eliminate this confusion.
- **Unified Assignment:** `logic` can be used interchangeably for both continuous assignments and procedural assignments.
- **Single Driver Rule:** `logic` prevents multiple drivers from driving the same signal. If multiple `assign` statements or blocks try to drive the same `logic` variable, the compiler will throw an error. This catches accidental multi-driver bugs early (unlike `wire` which would silently resolve to `X`). 
*(Note: If true multi-drive resolution like a tri-state bus is needed, `wire` must still be used).*

## Question 2: Enumerated Data Types
**Write a SystemVerilog program to declare an enumerated data type using typedef named "dept_t" with members HR = 1, Finance = 5, Sales = 9, Production = 15, and Support = 21. Initialize an enum variable to Sales and display its name and value. Using built-in enum methods, display the first and last members of the enumeration and verify whether Admin is a valid member of the enum. (10 M)**

```verilog
module enum_question;
  
  // Declare the enumerated type
  typedef enum int {
    HR         = 1,
    Finance    = 5,
    Sales      = 9,
    Production = 15,
    Support    = 21
  } dept_t;

  dept_t dept;
  bit is_admin_valid = 0;

  initial begin
    // Initialize variable to Sales
    dept = Sales;
    
    // Display initialized name and value
    $display("Current Department: %s, Value: %0d", dept.name(), dept);
    
    // Display first and last members using built-in methods
    $display("First member: %s = %0d", dept.first().name(), dept.first());
    $display("Last member: %s = %0d", dept.last().name(), dept.last());
    
    // Verify whether "Admin" is a valid member
    dept = dept.first();
    for (int i = 0; i < dept.num(); i++) begin
      if (dept.name() == "Admin") begin
        is_admin_valid = 1;
        break;
      end
      dept = dept.next();
    end
    
    if (is_admin_valid)
      $display("Admin is a valid member of the enum.");
    else
      $display("Admin is NOT a valid member of the enum.");
  end
endmodule
```

**Expected Output:**
```
Current Department: Sales, Value: 9
First member: HR = 1
Last member: Support = 21
Admin is NOT a valid member of the enum.
```

## Question 3: String Processing
**Write a SystemVerilog program to process the string "System Verilog makes string handling simple". The program should count the total number of words in the string, identify the longest word, and display the longest word along with its length. (10 M)**

```verilog
module string_processing;
  
  string str = "System Verilog makes string handling simple";
  string current_word = "";
  string longest_word = "";
  int word_count = 0;
  byte c;
  
  initial begin
    $display("Original String: %s\n", str);
    
    // Iterate through string including one extra iteration for the final word
    for (int i = 0; i <= str.len(); i++) begin
      // Get character or space if at the end of string
      if (i < str.len()) 
        c = str[i];
      else 
        c = " "; 
        
      // Process on space delimiter
      if (c == " ") begin
        if (current_word.len() > 0) begin
          word_count++;
          // Check if it's the longest
          if (current_word.len() > longest_word.len()) begin
            longest_word = current_word;
          end
          // Reset for next word
          current_word = ""; 
        end
      end 
      else begin
        // Append character to current word
        current_word = {current_word, string'(c)};
      end
    end
    
    $display("Total number of words: %0d", word_count);
    $display("Longest word: %s", longest_word);
    $display("Length of longest word: %0d", longest_word.len());
  end
endmodule
```

**Expected Output:**
```
Original String: System Verilog makes string handling simple

Total number of words: 6
Longest word: handling
Length of longest word: 8
```

## Question 4: 2-D Arrays and Dynamic Arrays
**Write a SystemVerilog program to store temperature readings in a 2-D array representing four hourly readings for each of three days as {{28, 30, 32, 31}, {26, 29, 31, 33}, {30, 32, 35, 34}}. The program should calculate the average temperature for each day, identify the hottest day based on the highest average temperature, and create an additional array to store all temperature readings that are greater than their respective daily average. (10 M)**

```verilog
module array_temperatures;
  
  // 3 Days, 4 Readings each
  int temps[3][4] = '{
    '{28, 30, 32, 31},
    '{26, 29, 31, 33},
    '{30, 32, 35, 34}
  };
  
  real daily_avg[3];
  real highest_avg = 0.0;
  int hottest_day = 0;
  
  int above_avg_temps[];
  int above_avg_count = 0;
  
  initial begin
    // 1. Calculate Average Temperature and Hottest Day
    for (int i = 0; i < 3; i++) begin
      int sum = 0;
      for (int j = 0; j < 4; j++) begin
        sum += temps[i][j];
      end
      
      daily_avg[i] = sum / 4.0;
      $display("Day %0d Average Temperature: %0.2f", i+1, daily_avg[i]);
      
      if (daily_avg[i] > highest_avg) begin
        highest_avg = daily_avg[i];
        hottest_day = i + 1;
      end
    end
    
    $display("\n=> Hottest Day is Day %0d with an average of %0.2f\n", hottest_day, highest_avg);
    
    // 2. Count temperatures above daily average
    for (int i = 0; i < 3; i++) begin
      for (int j = 0; j < 4; j++) begin
        if (temps[i][j] > daily_avg[i]) begin
          above_avg_count++;
        end
      end
    end
    
    // 3. Allocate dynamic array and populate
    above_avg_temps = new[above_avg_count];
    above_avg_count = 0; // reset for indexing
    
    for (int i = 0; i < 3; i++) begin
      for (int j = 0; j < 4; j++) begin
        if (temps[i][j] > daily_avg[i]) begin
          above_avg_temps[above_avg_count] = temps[i][j];
          above_avg_count++;
        end
      end
    end
    
    $display("Readings greater than their daily average: %p", above_avg_temps);
  end
endmodule
```

**Expected Output:**
```
Day 1 Average Temperature: 30.25
Day 2 Average Temperature: 29.75
Day 3 Average Temperature: 32.75

=> Hottest Day is Day 3 with an average of 32.75

Readings greater than their daily average: '{32, 31, 31, 33, 35, 34}
```

## Question 5: Associative Arrays
**Write a SystemVerilog program to use an associative array to store the number of login attempts made by users, where the username is the key and the number of login attempts is the value, given as Amit = 3, Rahul = 7, Suman = 2, Neha = 6, and Priya = 5. Traverse the associative array to identify and display all users whose login attempts exceed a security limit of 5 attempts. The program should also calculate and display the total number of login attempts made by all users and list the names of users whose login attempts are above the average number of attempts. (10 M)**

```verilog
module associative_login_tracker;
  
  // string key, int value
  int logins[string] = '{
    "Amit" : 3, 
    "Rahul": 7, 
    "Suman": 2, 
    "Neha" : 6, 
    "Priya": 5
  };
  
  int total_attempts = 0;
  real avg_attempts;
  
  initial begin
    // 1. Identify users exceeding security limit of 5
    $display("--- SECURITY ALERT: Exceeded 5 Attempts ---");
    foreach (logins[name]) begin
      if (logins[name] > 5) begin
        $display("User: %s (Attempts: %0d)", name, logins[name]);
      end
      
      // Keep a running total
      total_attempts += logins[name];
    end
    
    // 2. Calculate and display total and average
    $display("\n--- STATS ---");
    $display("Total Login Attempts: %0d", total_attempts);
    
    avg_attempts = real'(total_attempts) / logins.num();
    $display("Average Login Attempts: %0.2f", avg_attempts);
    
    // 3. List users above average
    $display("\n--- USERS ABOVE AVERAGE ---");
    foreach (logins[name]) begin
      if (logins[name] > avg_attempts) begin
        $display("- %s (%0d attempts)", name, logins[name]);
      end
    end
  end
endmodule
```

**Expected Output:**
```
--- SECURITY ALERT: Exceeded 5 Attempts ---
User: Neha (Attempts: 6)
User: Rahul (Attempts: 7)

--- STATS ---
Total Login Attempts: 23
Average Login Attempts: 4.60

--- USERS ABOVE AVERAGE ---
- Neha (6 attempts)
- Priya (5 attempts)
- Rahul (7 attempts)
```
